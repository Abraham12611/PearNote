# Source ingestion and subject classification system

## Scope and requirements

**Phase 1:** PDF and pasted/plain text only; user owns the source; classifying mixed subjects is central. **Later:** DOCX/PPTX, image notes, audio, MP4, authorized YouTube transcripts, webpage capture, digital books. No physical hardware.

## Processing pipeline

| Stage | Work | Required evidence/output |
|---|---|---|
| 0 Upload | Validate MIME, size and ownership; compute checksum | `sourceId`, storage reference, dedupe hint |
| 1 Parse | Extract PDF text by page; text pasted by paragraph | page/line/segment references, extraction warnings |
| 2 Normalize | Preserve original order, headings, definitions, figures as links if parsed | stable segment IDs, not just one giant prompt |
| 3 Classify | Meta model suggests 1..N subjects with `segmentIds`, explanation and uncertainty | typed subject proposals; no writes to final subjects |
| 4 Review | Student can rename, merge, split, discard, reassign | user-approved mapping |
| 5 Index | Index authorized chunks for targeted grounded retrieval | source filters, storage refs, embeddings where used |
| 6 Knowledge | Extract concepts, candidate dependencies, learning objectives | graph draft with passage evidence |
| 7 Curriculum | Generate sections/units/lessons and coverage map | validated draft version |
| 8 Publish | Create authorized subjects/lesson spaces after validation | IDs and generation statuses |

## Multi-subject design

Classification should work **per segment**, not assume one file = one subject. One file might have 30 pages of biology and 20 pages of chemistry. The proposal UI groups segments under suggested subjects, while letting students reassign them. Source file ownership remains single; `subjectSources` relates relevant segments to multiple subjects. If confidence is low or segments overlap, show `Needs review` and ask the student.

## PDF/text specifics

- MIME and extension validation both required; guard against malicious or enormous files.
- Password-protected or image-only PDFs should be flagged rather than claiming text was read. OCR may be introduced later with clear limits.
- Store page offsets and paragraph IDs; never manufacture source page references.
- Handle malformed encodings, tables, formulas and fragmented text with warnings.
- Text paste has a stable source title + original raw content; preserve it unchanged for audit.
- If 0 meaningful content extracted: show failed/needs-input; don't invent subject/curriculum.

## Source-grounding contract

Every generated concept has `sourceRefs[]`; every factual lesson explanation has citations or is clearly marked supplemental general background. A citation stores original sourceId, segmentId, page/timestamp, quote range if available. Verification should check that segment belongs to an authorized source and substantively supports the statement. `Generated by AI` alone is not a citation.

## Job and review state

Use `uploaded -> extracting -> classifying -> needs_review -> planning -> validating -> ready`, plus `failed`, `cancelled`. Job resumability and retry allowed. Once a student edits a proposal, later auto-runs must not overwrite user adjustments without a new review step.

## Future media additions

- Audio: speech-to-text with timestamp/diarization if available; show transcription confidence and permit corrections.
- Video: transcript + selected frames/clips; avoid analyzing every frame by default. Do not claim a model watched frames not actually processed.
- YouTube: obtain captions/media only through authorized means and respect service rules.
- DOCX/PPTX: structural parsing plus figures/slides and speaker notes; track source section.
- Images/science diagrams: extracted labels, source-image crop, caution for accuracy. SAM optional for interactive regions.

## Acceptance tests

Single-topic PDF, mixed-subject PDF, manual text, duplicate PDF, no-text scanned PDF, invalid MIME, huge PDF, broken parsing, ambiguous chapter, cross-user access denial, interrupted job resume. Assert no subject gets created before user approval of a multi-subject proposal.
