### Deployment env (set via `npx convex env set` on `keen-marten-701`)

| Var | Value | Status |
|---|---|---|
| `JWT_PRIVATE_KEY` / `JWKS` | generated by `npx @convex-dev/auth` | ✅ real — anonymous guest sign-in works |
| `SITE_URL` | `http://localhost:5173` | ✅ set; only matters for OAuth/OTP redirect flows, not anonymous guests |
| `FIRECRAWL_API_KEY` | `PREVIEW_PLACEHOLDER_NO_REAL_KEY` | ⚠️ placeholder — link→card enrichment will fail fast if invoked |
| `AGENTMAIL_API_KEY` | `PREVIEW_PLACEHOLDER_NO_REAL_KEY` | ⚠️ placeholder — space inbox/OTP email will fail fast if invoked |
| `AI_GATEWAY_DISABLED` | `1` | ✅ intentional — disables the one AI-gateway call (embeddings) |

Push-time validation in `convex/convex.config.ts` **requires**
`FIRECRAWL_API_KEY` and `AGENTMAIL_API_KEY` — that is why placeholders exist.
They are deliberately invalid values so misuse fails loudly, not silently.

**To replace a placeholder:** `npx convex env set FIRECRAWL_API_KEY <real>` —
needs the real key from the owner. Never commit real values.

## 5. Reproduce / re-push

```bash
# from a clean checkout of the desired branch — pushes committed code only
git worktree add --detach /tmp/pn-backend <branch>
cd /tmp/pn-backend && npm ci
npx convex dev --once          # pushes to dev:keen-marten-701 via .env.local
npx convex run seed:seedCrew   # re-seed if needed
```

`.env.local` lives only locally (gitignored). The Vercel preview never reads
it — it uses project env vars.

## 6. Blockers / risks

1. **Placeholder API keys** — firecrawl/agentmail features fail fast if
   invoked; owner supplies real keys when needed.
2. **Dev deployment is shared** — every engineer's `convex dev` pushes to
   `keen-marten-701`; concurrent pushes last-write-win. Consider per-engineer
   dev deployments (`npx convex dev` per person) once the team grows.
3. **Functions were pushed at `367f74e`** — uncommitted schema/UI work in the
   shared tree is NOT on the deployment. After PRs merge, re-push.
4. **Prod `wooden-rat-386` exists but empty** — any accidental
   `npx convex deploy` would create a live prod. Branch-protection + owner
   discipline are the guard; there is no technical barrier yet.
5. **`roomsOpen` gate** — "new space" creation is disabled on non-upstream
   deployments (`convex/spaces.ts:167`); seeded rooms are the only spaces
   until that gate is re-keyed (Phase 00.5).
